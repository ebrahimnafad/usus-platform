# 0011 - Print Button Uses PDF-Through-Iframe Instead of window.print()

The browser print button fetches the server-rendered PDF from `/api/pdf`, loads it into a hidden `<iframe>`, and calls `iframe.contentWindow.print()` rather than invoking `window.print()` directly on the live DOM. This guarantees pixel-perfect parity between the printed worksheet and the downloaded PDF — both pass through the same Playwright headless-browser pipeline with identical A4 layout, 2-page budget scaling, `print-color-adjust: exact`, and zero-margin `@page` rules. The trade-off is a brief network round-trip and loading state before the print dialog appears, and a more complex error path if the PDF API is unreachable. We accepted this because the `window.print()` path produced 4-page output (vs. the PDF's 2 pages), leaked shell chrome (mobile bottom bar), and had no scale budget enforcement — making printed and downloaded worksheets visually inconsistent for teachers.
